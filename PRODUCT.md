# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Modern builders: indie founders, frontend developers, designers using AI for exploration, and small studios that need a credible visual and technical starting point before shipping a website.

## Product Purpose

Framefield is a curated library of art-directed website builds, reusable sections, visual assets, and prompts. It helps visitors choose a stronger starting direction and move toward a shippable result faster.

## Positioning

Unlike a broad template dump, every library item is a deliberately authored, independently previewable build with a clear visual direction and implementation path.

## Operating Context

Visitors browse the Framefield landing-page library, inspect an item in a dedicated full-screen preview, and use the asset as a starting point for their own work. The catalog is maintained in the repository while source delivery, licensing, accounts, and payments remain out of scope.

## Capabilities and Constraints

- The running product is a Next.js web application.
- Library assets can be sections, websites, visuals, or prompts, each with standalone metadata and preview media.
- New non-hero preview routes have no navbar or footer; their only Framefield connection is a `Back to library` control.
- `sourceAvailable` means code and/or a prompt exists in the repository; it does not imply download, licensing, authentication, or a purchase flow.
- NORTHSTAR Testimonials and its Atlas House proof story are explicitly fictional demonstration content.

## Brand Commitments

Framefield is dark, editorial, and tool-like, with acid lime reserved as an action accent. Catalog previews are independent visual worlds: they do not inherit the Framefield brand beyond the universal return control.

## Evidence on Hand

- Existing product and implementation documentation in `docs/`.
- Original supplied testimonial reference screenshots are stored as reference material only.
- NORTHSTAR is an approved fictional performance-partner concept; its visual assets and claims must be authored as illustrative material, not presented as client evidence.

## Product Principles

- Curate fewer, more distinct starting points.
- Keep each library item independently understandable and usable.
- Let proof be explicit about what is real, fictional, or illustrative.
- Prioritize responsive, accessible implementation over catalog chrome.
